# Temporary UNC Asheville tower-camera refresh

This local-only refresh replaces the stale WLOS image on the Sunset Radiance page without recurring Git commits, Vercel builds, or visitor-triggered video processing.

## Architecture

1. Windows Task Scheduler runs `Refresh-Towercam.ps1` every 15 minutes.
2. A HEAD request checks UNC Asheville's current `towercam.jpg` `ETag`, `Last-Modified`, and `Content-Length`. If all are unchanged, the run stops there.
3. When the source changes, the script downloads that one JPEG. If the direct JPEG is unavailable, it falls back to FFmpeg seeking from 0.5 seconds before the end of the supplied MP4 and extracts one frame using one encoder thread.
4. The JPEG SHA-256 is compared with the last successful image. An identical frame is not uploaded.
5. Because Vercel sensitive values cannot be pulled to this PC, the script requests a short-lived upload signature from a tiny authenticated Vercel route only after the image changes. The MP4 and JPEG never pass through Vercel. If usable Cloudinary credentials are supplied locally later, the script signs locally and skips this call.
6. A direct-to-Cloudinary upload overwrites the single public ID `avlweather_towercam_latest` and invalidates its old CDN copy.
7. The page uses one stable Cloudinary URL and a shared 15-minute cache key, so visitors in the same refresh window reuse the same browser/CDN object.

Runtime state is outside the repository at `%LOCALAPPDATA%\828WeatherDirect\towercam-refresh`. Nothing generated by the scheduled job is committed or deployed.

## Install and run

curl is required; FFmpeg is required only for the MP4 fallback. This machine's Vercel pull represents sensitive Cloudinary variables as `[SENSITIVE]`, so a one-time shared refresh token must be configured before the next normal production deployment:

```powershell
& "C:\Users\Tim\828codeproject\828-weather-direct\tools\towercam-refresh\Initialize-TowercamSigner.ps1"
```

The setup script stores the generated token only under `%LOCALAPPDATA%` and adds the matching value to Vercel as a sensitive production environment variable. It does not deploy the site.

After the code containing the new signing route and page URL has gone through the next normal production deployment, install the scheduled task:

```powershell
& "C:\Users\Tim\828codeproject\828-weather-direct\tools\towercam-refresh\Install-TowercamTask.ps1" -RunNow
```

The task name is `828 Weather Direct Towercam Refresh`. It runs as the current Windows user every 15 minutes. A changed image causes one small authenticated Vercel signing request; unchanged checks cause none.

For a manual diagnostic refresh:

```powershell
& "C:\Users\Tim\828codeproject\828-weather-direct\tools\towercam-refresh\Refresh-Towercam.ps1" -Force
```

The latest status is stored in `state.json`. If a run fails, `last-error.txt` contains the most recent error. Both are in `%LOCALAPPDATA%\828WeatherDirect\towercam-refresh`.

## Measured source behavior (September 8, 2026)

The UNCA server returned `Accept-Ranges: bytes` for the supplied MP4. Across two successful FFmpeg `-sseof -0.5` tests, it used four ranged HTTP requests and read about 28-58 MB rather than the full roughly 1.18 GB file; the tests used about 2.6-5.8 CPU-seconds and peaked near 265-285 MB of memory.

The same server also exposes `https://www.atms.unca.edu/currwx/towercam.jpg`. It was a valid 2592x1984 JPEG measuring 1,577,586 bytes. In a side-by-side check at 11:57 AM, its embedded frame time was 11:56:06 while the MP4's final frame was 11:25:06. The direct JPEG is therefore both cheaper and fresher and is the normal source; the MP4 is fallback-only.

At four scheduled checks per hour, normal source traffic is roughly 6.3 MB/hour (about 151 MB/day) plus a similar upload total before Cloudinary compression/delivery optimization. Routine image processing is zero. Vercel receives at most one lightweight signature request per changed frame (about 96/day), with no video transfer, image processing, scheduled build, or redeploy. Git receives no recurring changes.

## Disable or remove

Disable without deleting:

```powershell
schtasks.exe /Change /TN "828 Weather Direct Towercam Refresh" /Disable
```

Re-enable:

```powershell
schtasks.exe /Change /TN "828 Weather Direct Towercam Refresh" /Enable
```

Remove the task:

```powershell
schtasks.exe /Delete /F /TN "828 Weather Direct Towercam Refresh"
```

After removing the task, the local runtime folder can be deleted. To fully revert the website, restore the former UNCA camera URL in `public/828-sunset-radiance.html`; the Cloudinary asset may then be deleted from the Media Library.
